# v0.2 Design — Cloud Sources

Status: design, ready for Dev implementation.
Scope: Google Drive (personal) + OneDrive (personal). No Business tenants, no
Google Workspace domains, no Google Docs/Sheets/Slides (they have no bytes to
hash), no Dropbox / iCloud Drive / Box.

This document is a contract between the Design and Dev agents. Every function
signature, table column, error class name, config key, CLI flag, and file path
below is intentional — the Dev agent may refine internal helpers, but public
shapes and on-disk artifacts SHOULD land exactly as written.

## 0. Guiding principles (recap from the plan)

- **Prefer local.** Local under an `active_home` wins any cross-source tie.
- **Never delete singletons.** A file with exactly one copy across every
  configured source is never a discard candidate.
- **Shared files are informational only.** If the API says the file was
  authored / owned by someone else, we never propose to trash it.
- **Read + trash only, never hard-delete.** OAuth scopes are chosen to make
  hard-delete physically impossible.
- **Undo works for cloud discards too.** Trash restore is a first-class API
  call, dispatched by `source_id`.

Everything else is derived from these four rules.

### 1.1 Types (`sources/base.py`)

```python
from __future__ import annotations

from collections.abc import Iterator
from dataclasses import dataclass, field
from pathlib import Path
from typing import Protocol, runtime_checkable


# Algo-tagged hash string. Examples:
#   "blake3:9f8e7d..."   (local, computed by hash/pipeline.py)
#   "md5:d41d8c..."      (Google Drive, from files.list)
#   "sha256:e3b0c4..."   (OneDrive Personal, from Graph)
ForeignHash = str


@dataclass(frozen=True)
class SourceMetadata:
    """Cloud-side metadata pulled during list_files().

    Populated for every cloud source; local source returns an empty
    SourceMetadata (all fields None / False).
    """

    etag: str | None = None
    cloud_file_id: str | None = None
    owner: str | None = None
    is_shared: bool = False
    parent_path: str | None = None  # human-readable "My Drive/Foo/Bar"


@dataclass(frozen=True)
class TrashedLocation:
    """Result of move_to_trash() — enough to restore later."""

    source_id: str
    cloud_file_id: str | None            # cloud sources only
    cloud_trash_id: str | None           # cloud sources only, if distinct
    local_trashed_at_path: Path | None   # local source only
    original_path: str                   # display path


@runtime_checkable
class Source(Protocol):
    """Every file-access backend implements this protocol."""

    @property
    def id(self) -> str:
        """Stable identifier, e.g. 'local' or 'gdrive:personal'."""

    def list_files(self) -> Iterator[FileRecord]:
        """Enumerate every eligible file. Streaming — never buffers whole
        listing in memory."""

    def read_bytes(
        self, record: FileRecord, chunk_size: int = 1 << 20
    ) -> Iterator[bytes]:
        """Stream the file content in ``chunk_size`` pieces.

        Cloud implementations MUST NOT materialize the whole file in memory
        or on disk — a 10 GB video download has to work on a laptop.
        """

    def move_to_trash(self, record: FileRecord) -> TrashedLocation:
        """Move the file to the source's trash / recycle bin. Idempotent
        callers pass in the same record twice at their peril — the second
        call may raise NotFoundError."""

    def restore_from_trash(self, loc: TrashedLocation) -> None:
        """Undo a move_to_trash(). Raises NotFoundError if the trashed
        object has been permanently deleted."""

    def get_metadata(self, record: FileRecord) -> SourceMetadata:
        """Return current metadata. Cloud sources may re-fetch to detect
        etag changes since list_files()."""
```

The `Protocol` shape is deliberate — `Source` is duck-typed, so a
`FakeSource` in tests doesn't have to inherit anything. The `@dataclass`
carriers and exceptions live alongside for one-stop imports.

### 1.2 `LocalFileSystemSource` (`sources/local.py`)

Refactoring goal: keep `scan/walk.py` mostly intact. Wrap `iter_files()` in a
thin class. Behaviour must not change.

```python
class LocalFileSystemSource:
    id = "local"

    def __init__(
        self,
        roots: list[Path],
        *,
        follow_symlinks: bool = False,
        exclude_globs: list[str] | None = None,
        min_size_bytes: int = 0,
        bundle_extensions: tuple[str, ...] | list[str] | None = None,
        stats: WalkStats | None = None,
    ) -> None: ...

    def list_files(self) -> Iterator[FileRecord]:
        return iter_files(
            self.roots,
            follow_symlinks=self.follow_symlinks,
            exclude_globs=self.exclude_globs,
            min_size_bytes=self.min_size_bytes,
            bundle_extensions=self.bundle_extensions,
            stats=self.stats,
        )

    def read_bytes(self, record, chunk_size=1 << 20):
        with record.path.open("rb") as f:
            while chunk := f.read(chunk_size):
                yield chunk

    def move_to_trash(self, record) -> TrashedLocation:
        # existing send2trash + basename-diff logic from apply/mover.py
        ...

    def restore_from_trash(self, loc) -> None:
        # existing shutil.move logic from apply/undo.py
        ...

    def get_metadata(self, record) -> SourceMetadata:
        return SourceMetadata()  # local has none
```

The mover and undo code in `apply/` already contain the local trash / restore
logic; sub-phase 1 moves it behind this class **without moving files** — the
mover simply calls the source's method. Zero behaviour change is required to
keep all 110+ existing tests green.

`scan/walk.py` stays where it is. `LocalFileSystemSource` is a thin façade,
NOT a rewrite.

The existing frozen dataclass in `scan/walk.py` grows six optional fields.
All defaults preserve local behaviour.

```python
@dataclass(frozen=True)

    path: Path
    size: int
    mtime: float
    inode: int
    dev: int
    nlink: int
    is_archive_member: bool = False
    is_bundle: bool = False
    precomputed_full_hash: str | None = None

    # v0.2 additions:
    source_id: str = "local"
    foreign_hash: ForeignHash | None = None
    etag: str | None = None

    owner: str | None = None
```

Rationale for defaults: existing walker code constructs `FileRecord(...)`

### 2.1 SQLite schema migration

The existing `files` table (defined in `store.py`) picks up the extra columns
with `ALTER TABLE`. A new `cloud_hash_cache` table stores computed BLAKE3
hashes for cloud files. Migration runs on the next `Store()` construction.

```sql
-- Migration v0.2 (run once at Store __init__ when schema_version < 2)

ALTER TABLE files ADD COLUMN source_id   TEXT NOT NULL DEFAULT 'local';
ALTER TABLE files ADD COLUMN foreign_hash TEXT;
ALTER TABLE files ADD COLUMN etag         TEXT;
ALTER TABLE files ADD COLUMN cloud_file_id TEXT;
ALTER TABLE files ADD COLUMN owner        TEXT;
ALTER TABLE files ADD COLUMN is_shared    INTEGER NOT NULL DEFAULT 0;

-- The existing PRIMARY KEY (path) works if we make cloud paths unique per
-- source. Cloud paths get a virtual scheme prefix in the ``files.path``
-- column: "gdrive:personal://My Drive/foo/bar.pdf" — that guarantees no
-- collision with local paths. All cloud queries filter by source_id first.

CREATE INDEX IF NOT EXISTS idx_files_source_hash
    ON files(source_id, full_hash);
CREATE INDEX IF NOT EXISTS idx_files_source_foreign
    ON files(source_id, foreign_hash);

-- Cache of BLAKE3 hashes computed from cloud files, keyed by
-- (source_id, cloud_file_id, etag). Long-lived — invalidated only when
-- etag changes. Insert-only; a stale row (etag no longer current) simply
-- doesn't match a lookup.
CREATE TABLE IF NOT EXISTS cloud_hash_cache (
    source_id     TEXT NOT NULL,
    cloud_file_id TEXT NOT NULL,
    etag          TEXT NOT NULL,
    blake3_hash   TEXT NOT NULL,
    computed_ts   REAL NOT NULL,
    size          INTEGER NOT NULL,
    PRIMARY KEY (source_id, cloud_file_id, etag)
);
CREATE INDEX IF NOT EXISTS idx_cloud_hash_cache_hash
    ON cloud_hash_cache(blake3_hash);

-- Schema version marker so future migrations know what has already run.
CREATE TABLE IF NOT EXISTS schema_meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
INSERT OR REPLACE INTO schema_meta (key, value) VALUES ('version', '2');
```

`Store.__init__` reads `schema_meta.version`, treats missing as "1", and
runs the ALTERs when < 2. All ALTERs are idempotent-safe because SQLite
raises `OperationalError: duplicate column name` if run twice; catch and
ignore that specific case so re-runs are safe.

## 3. Hash reconciliation

### 3.1 The bucket-by-size stage still runs first

`hash/pipeline.py` groups by exact byte size before hashing. That gate is
now the most valuable optimisation for cloud sources: any cloud file whose
size doesn't match anything else in the scan can be dropped without a
byte-transfer. Enforced by pushing every source's `FileRecord` stream into
the existing `scan_stage` table (columns extended with `source_id`,
`foreign_hash`, `cloud_file_id`, `etag`), then reading back per-size
buckets exactly as today.

### 3.2 The four cases per size bucket

Once a size bucket has ≥ 2 members from possibly different sources, we look
at the `foreign_hash` algorithm prefix on each member:

```
                                 same algo across
                                 all members?
                              ┌─────────┴─────────┐
                             YES                  NO
                              │                    │
              group by that algo prefix       any local member?
                (cheapest — zero I/O)         ┌────┴────┐
                                            YES         NO
                                             │           │
                          reconcile: BLAKE3    all cloud — need BLAKE3
                          on cloud members     on every cloud member,
                          only, cache-backed;  cache-backed;
                          local BLAKE3 already local file (none) skipped
                          in cache
```

Reconciliation always terminates in a single canonical BLAKE3 space for the
bucket. Every cloud member's BLAKE3 is written into `cloud_hash_cache`
keyed on `(source_id, cloud_file_id, etag)`. The next scan finds the row on
lookup and skips the download entirely — until the etag changes.

### 3.3 Algorithm (`hash/reconcile.py`, new module)

```python
def reconcile_bucket(
    members: list[FileRecord],
    sources: dict[str, Source],
    store: Store,
) -> Iterator[HashedRecord]:
    """Yield HashedRecords with BLAKE3 full_hash for every member.

    Contract: (a) never downloads a member whose foreign_hash algo matches
    every other member in the bucket, (b) never downloads a member whose
    (source_id, cloud_file_id, etag) is already in cloud_hash_cache."""
```

- If all members carry the same `foreign_hash` algo prefix (e.g. all local
  BLAKE3, or all Google MD5), yield them directly using that hash. No
  downloads.
- Otherwise: for each cloud member, look up
  `cloud_hash_cache[source_id, cloud_file_id, etag]`. If hit, use it. If
  miss, stream `source.read_bytes(rec)` through `blake3.blake3()`, insert
  the row, yield.
- Local members are already BLAKE3-hashed by the existing pipeline; the
  local-in-cloud case just uses the cached local hash.

### 3.4 Cache invalidation

The cache is keyed on etag. If Google/Microsoft return a new etag for the
same `cloud_file_id`, the primary-key lookup misses and we recompute. Stale
rows are never read again but stay on disk — `dc cache clear` truncates the
table when the user wants a hard reset.

### 3.5 Bandwidth cost bound

Worst case is the first scan of a 10 GB Google Drive when local has zero
hash-compatible members. We mitigate three ways:

1. **Size-singleton skip.** A cloud file whose size matches nothing else in
   the whole scan is a singleton across sources — no download, no hash.
   This alone eliminates the majority of a real-world Drive.
2. **Cross-cloud same-algo skip.** Google is MD5 and OneDrive is SHA-256.
   Different sources rarely share an algo, so this only saves work when
   two Google accounts (or two OneDrive accounts) are configured together
   — plausible, but not the common case.
3. **Cache forever.** After the first successful scan every cloud file is
   BLAKE3-cached and later scans do zero downloads until an etag changes.

The scan progress bar (from `sys/monitor.py`) MUST show
`downloaded_bytes / to_download_bytes` so the user sees when a bucket
requires streaming. A `--max-cloud-download-mb` CLI flag caps the total
per-scan cloud bytes (default: unlimited); when the cap is hit, the scan
records remaining buckets as "not-yet-hashed" in the report and continues.

## 4. OAuth flow

### 4.1 Client registration — recommendation

**Ship the tool WITHOUT an embedded default OAuth client. Require the user
to bring their own.**

Why: both Google and Microsoft treat installed / desktop app client secrets
as non-secret in principle, but distributing a real client_id + secret in a
publicly-hosted repo creates three real problems:

- **Rate limits shared.** Every user of the tool would share one client's
  per-project quota (Google Drive: 1B queries/day/project, 1000/100s/user).
  A viral popularity moment could brownout everyone.
- **Provider ToS.** Google requires each publicly-distributed OAuth client
  to be through the App Verification process — expensive, and it enables
  Google to disable the client for any policy violation, kicking every
  user off at once.
- **Repudiation.** If any user misbehaves (mass-downloads, uses the tool
  for prohibited purposes), the whole client can be revoked and blocked.

The BYO-client flow is a five-minute one-off setup per user, documented in
`docs/cloud-oauth-setup.md` (Docs agent owns this in sub-phase 2). The
setup UX is `dc auth add gdrive`, which prints:

```
DuplicateCleaner needs an OAuth client to talk to Google Drive on your
behalf. Create one at:

  https://console.cloud.google.com/apis/credentials
    → Create Credentials → OAuth client ID
    → Application type: Desktop app

Paste the client ID: _
Paste the client secret: _
```

Then it proceeds with the localhost callback dance.

### 4.2 Localhost callback flow

Implementation notes:

- Random port: `socket.bind(("127.0.0.1", 0))` then read `getsockname()[1]`.
  Register the exact `http://127.0.0.1:{port}/oauth/callback` as the
  redirect URI on the fly? No — both providers require the redirect URI to
  be pre-registered against the OAuth client. Standard workaround: register
  `http://127.0.0.1` at any port (Google explicitly supports "loopback IP
  address" as a whitelisted redirect scheme; Microsoft supports
  `http://localhost` with any port on public-client desktop app
  registrations). The setup docs tell the user to whitelist
  `http://127.0.0.1` in their client registration.
- Use `http.server.HTTPServer` on a background thread; the CLI blocks until
  the callback comes in or a 120 s timeout elapses.
- The callback page shows a plain HTML "You may close this window" and
  contains a small `<script>` that closes the tab; no JavaScript to eval
  from the provider.

### 4.3 Token storage — repo-local, `chmod 600`

The plan-file version said macOS Keychain. **User has overridden to
repo-local.** Design:

```
~/.config/duplicate_cleaner/
├── config.toml         # existing v0.1.1 config
├── accounts.toml       # NEW: registered accounts
├── weights.json        # existing
└── tokens/
    ├── gdrive:personal.json      # chmod 600
    └── onedrive:personal.json    # chmod 600
```

Each token file:

```json
{
  "account_id": "gdrive:personal",
  "type": "gdrive",
  "user_email": "vaannada@gmail.com",
  "client_id": "...",
  "client_secret": "...",
  "access_token": "...",
  "refresh_token": "...",
  "expires_at": 1741234567.0,
  "scopes": ["https://www.googleapis.com/auth/drive.file"]
}
```

Rules enforced by `sources/auth/tokens.py`:

- `os.chmod(path, 0o600)` on write. Verify permissions on read; refuse to
  use a token file that's world- or group-readable, print a warning telling
  the user to fix perms.
- Parent directory `~/.config/duplicate_cleaner/tokens/` is created with
  mode `0o700`.
- Refresh tokens are long-lived; treat as sensitive. Log statements MUST
  redact any string longer than 20 chars matching `access_token` or
  `refresh_token` context.
- `dc auth remove <id>` deletes the file and revokes at the provider
  (`POST` to Google `oauth2/revoke` / Microsoft `logout` endpoints,
  best-effort — proceed even if the revoke call fails).

### 4.4 Scopes (locked in)

| Provider  | Scope                                          |
|-----------|------------------------------------------------|
| Google    | `https://www.googleapis.com/auth/drive.file`   |
| Microsoft | `Files.ReadWrite` + `offline_access`           |

`drive.file` restricts access to files the app itself created OR that the
user explicitly picked via the Drive Picker — this is too tight to enumerate
someone's whole Drive.

For a full-drive enumerator the user must consent to
`https://www.googleapis.com/auth/drive` (broad read/write). The plan file
locks scopes to `drive.file`. Design decision: **honor the plan.** The tool
will only see files it (or previously the user via a Drive Picker) has
touched. For a first-run migration workflow, the user must run
`dc auth grant-drive-picker` (implemented via Google Drive UI Picker) to
enumerate arbitrary folders. This is called out explicitly to the user in
`dc auth add gdrive`.

If the user later wants full-drive scope, `dc auth add gdrive --full` uses
`.../auth/drive` — but the default remains `drive.file`.

## 5. API integrations

### 5.1 Google Drive — `sources/gdrive.py`

Client choice: **`google-api-python-client` + `google-auth-oauthlib`.**

- Justification: it's the reference client, ships batching, transparently
  handles refresh-on-401, and its `MediaIoBaseDownload` streams cleanly for
  `read_bytes`. The heavier surface area is fine because we call ~4
  distinct endpoints.

Key calls:

- **Enumerate** — `files.list(q=None, spaces='drive', pageSize=1000,
  fields='nextPageToken, files(id,name,size,md5Checksum,modifiedTime,parents,owners,shared,trashed,mimeType)')`
  Skip `trashed=true`. Skip `mimeType` starting with
  `application/vnd.google-apps.` (Docs/Sheets/Slides — no bytes to hash).
  Reconstruct `parent_path` by walking `parents` lazily with a per-scan
  `dict[folder_id, folder_meta]` cache.
- **Read bytes** — `files.get_media(fileId=id)` + `MediaIoBaseDownload`
  with `chunksize=chunk_size`. Yields chunks.
- **Trash** — `files.update(fileId=id, body={"trashed": True},
  fields="id,trashedTime")`. Returns updated metadata; there is no separate
  "trash id" — the same file id is used to restore. `TrashedLocation` sets
  `cloud_file_id=id` and `cloud_trash_id=None`.
- **Restore** — `files.update(fileId=id, body={"trashed": False})`.
- **Retries** — wrap every call with `tenacity.retry(
  retry=tenacity.retry_if_exception_type((HttpError,)),
  wait=tenacity.wait_exponential(multiplier=1, min=1, max=60),
  stop=tenacity.stop_after_attempt(5))` and a custom filter that only
  retries on HTTP 429 and 5xx.
- **foreign_hash format** — `md5:{md5Checksum}`. Google returns nothing for
  Google Docs / very small edge cases — treat missing checksum as
  "no foreign hash", which forces the reconcile step to stream-hash.

### 5.2 Microsoft Graph (OneDrive Personal) — `sources/onedrive.py`

Client choice: **`httpx` + `msal`.** No `msgraph-sdk`.

- Justification: `msgraph-sdk` is asyncio-first, brings in Kiota generators,
  and its models change frequently. `httpx` is already a candidate we might
  want later for other HTTP work, and Graph's REST surface is tiny for our
  four calls. `msal` handles the token cache and refresh cleanly.

Key calls (all against `https://graph.microsoft.com/v1.0`):

- **Enumerate** — `GET /me/drive/root/children` first, then per-folder
  `GET /me/drive/items/{id}/children?$top=200&$select=id,name,size,file,folder,lastModifiedDateTime,parentReference,createdBy,shared,remoteItem,deleted,eTag`.
  DFS through folders. Skip anything with `remoteItem` (shared-with-me
  content shows up here for OneDrive Personal). Skip `folder` items for
  enumeration purposes but recurse into them.
- **foreign_hash** — `sha256:{item.file.hashes.sha256Hash}`. OneDrive
  Personal populates `sha256Hash` reliably. OneDrive Business gives
  `quickXorHash` which we don't handle — reject Business tenants at
  auth-add time by checking the token's `tid` claim.
- **Owner check** — `createdBy.user.id` compared against the account's own
  `id` (fetched once per source from `GET /me`). `is_shared` = True if
  `createdBy.user.id` differs OR if the item exposes `shared` metadata.
- **Read bytes** — `GET /me/drive/items/{id}/content` with streaming
  (`with httpx.stream("GET", ...) as r: yield from r.iter_bytes(chunk_size)`).
  Graph returns a 302 to a pre-signed CDN URL; httpx follows automatically.
- **Trash** — `DELETE /me/drive/items/{id}`. Graph documents this as
  "moves to recycle bin" for Personal. No response body.
- **Restore** — this is where OneDrive Personal is annoyingly different
  from Business. Business supports
  `POST /me/drive/items/{id}/restore` cleanly. **Personal historically did
  not.** Design contract for Dev implementation:
  1. Try `POST /me/drive/items/{id}/restore` first. If 200/202, done.
  2. If 400/501/`itemNotFound` or explicit "not supported for personal",
     fall back to listing the recycle bin (`GET /me/drive/recycleBin` or
     the newer `GET /me/drive/special/recycle/children` if available) and
     issue `POST /me/drive/items/{id}/restore` on the found item.
  3. If neither works, raise `SourceError` with a clear message pointing
     the user at the OneDrive web UI to restore manually. Undo records the
     failure per-entry so successful entries still complete.
- **Retries** — same tenacity pattern as Google, retry on 429 and 5xx,
  honor `Retry-After` header when present.

### 5.3 Read-only-during-scan discipline

Both source implementations MUST expose an `is_read_only_scan: bool = True`
default. `move_to_trash` raises `PermissionError` when `is_read_only_scan`
is True — a runtime tripwire so a bug in `dc scan` cannot delete cloud
files. `apply/mover.py` explicitly constructs the source with
`is_read_only_scan=False`.

## 6. Deletion + undo semantics across sources

### 6.1 Manifest schema extension

`apply/mover.py` currently writes entries shaped like
`{original_path, size, mtime, hash, trashed_at_path}`. v0.2 adds three
fields, all optional; existing local-only manifests deserialise unchanged.

```json
{
  "created_at": "20260905T120000Z",
  "roots": ["/Users/vaannada/Documents"],
  "entries": [
    {
      "source_id": "local",
      "original_path": "/Users/vaannada/Documents/foo.pdf",
      "size": 12345,
      "mtime": 1741234567.0,
      "hash": "blake3:9f8e...",
      "trashed_at_path": "/Users/vaannada/.Trash/foo.pdf",
      "cloud_file_id": null,
      "cloud_trash_id": null
    },
    {
      "source_id": "gdrive:personal",
      "original_path": "gdrive:personal://My Drive/Old/foo.pdf",
      "size": 12345,
      "mtime": 1741234567.0,
      "hash": "md5:d41d...",
      "trashed_at_path": null,
      "cloud_file_id": "1AbCdEfGhIjKlMnOp",
      "cloud_trash_id": null
    }
  ]

```

### 6.2 Dispatch in `apply/mover.py` and `apply/undo.py`

Mover picks the right `Source` per entry by `source_id`:

```python
def _source_for(entry_or_member, sources_by_id):
    source_id = entry_or_member.get("source_id", "local")
    src = sources_by_id.get(source_id)
    if src is None:
        raise ApplyError(f"Report references unknown source: {source_id}")
    return src
```

Trash path — for each verified discard, call `src.move_to_trash(record)`,
merge the returned `TrashedLocation` into the manifest entry, flush after
every move (as today).

Restore path — for each manifest entry, resolve source by `source_id` and
call `src.restore_from_trash(TrashedLocation(...))`. The `LocalFileSystemSource`
implementation reuses the existing `_locate_by_basename_and_size` logic,
so v0.1.1 undo behaviour stays byte-identical for local-only manifests.

### 6.3 Failure modes

| Failure                                     | Behaviour                                              |
|---------------------------------------------|--------------------------------------------------------|
| Cloud file already permanently deleted      | `NotFoundError`; recorded per-entry; other entries continue |
| Cloud file was un-trashed by another client | Undo raises `AlreadyRestoredError`; skipped, counted   |
| Cloud API throttled                         | Tenacity retries; eventual failure surfaces as `RateLimitError` |
| Token expired mid-run                       | Auto-refresh from `refresh_token`; if refresh fails, `AuthExpiredError` |
| Network blip                                | `NetworkError`; retried per tenacity policy            |

The mover MUST NOT abort the whole apply run on a single entry failure —
it MUST continue and report per-entry status in the manifest and CLI
output, mirroring the existing local behaviour.

## 7. Scoring signals for cross-source (`score/rules.py`)

Three new signals. Weights added to defaults in `weights.json` on first
run; existing users get them via the "unknown key" merge in the config
loader.

```python
# New keys in the default weights dict:
"cloud_when_local_exists": -3.0,
"is_shared_file": 0.0,                # marker only; forces informational
"is_singleton_across_sources": 0.0,   # marker only; forces informational
```

### 7.1 Rules

- **`cloud_when_local_exists`** — if a group contains at least one member
  with `source_id == "local"` and this member's `source_id != "local"`,
  add the weight (default -3). Rationale: prefer local.
- **`is_shared_file`** — if the member's `is_shared` is True, mark
  `is_informational = True` (same channel already used by hardlinks and
  APFS clones). The scorer never proposes deleting an informational member.
- **`is_singleton_across_sources`** — set upstream when a hash appears in
  exactly one group member across all sources. Marks the member
  informational. Enforced BEFORE scoring so the "never delete singletons"
  rule is unconditional.

### 7.2 Interaction with hardlinks / clones

Informational is a monotone flag: once set, no other signal can undo it.
Existing hardlink and clone detection already sets `is_informational`;
shared / singleton simply add to the same set. The scorer then picks a
keeper from the remaining non-informational members — meaning a group of
{shared-cloud, local-under-active-home} picks the local as keeper and
never proposes a discard, because the only cloud member is informational.

For the standard case of {local-under-active-home, gdrive:personal}: local
scores +4 (active home), Google scores 0 -3 (cloud_when_local_exists) = -3;
local wins, Google is discard-proposed.

## 8. Testing strategy

Cloud integrations must NOT hit real APIs in unit tests. Three layers:

### 8.1 Unit tests — Source protocol conformance

Every real `Source` implementation passes a shared test suite in
`tests/sources/test_source_contract.py` that mocks the underlying
transport:

- Google: mock `googleapiclient.discovery.build().files()` return values.
- OneDrive: `respx` (works with httpx) to stub HTTP calls with recorded
  JSON bodies.

Assertions cover: `list_files()` yields expected records; `read_bytes()`
streams chunks; trash / restore issue the right calls with the right
arguments; error paths raise the correct exceptions.

### 8.2 `FakeSource` (`sources/fake.py`)

An in-repo Source implementation that reads from a local sidecar directory
with metadata files:

```
tests/fixtures/fake_source_a/
├── files/
│   ├── foo.pdf
│   └── bar.jpg
└── metadata.json     # etag, cloud_file_id, owner, is_shared per file
```

- `list_files()` walks `files/` and pairs each with its metadata entry.
- `read_bytes()` reads the local file.
- `move_to_trash()` moves the file into an internal `trash/` subdir and
  returns a `TrashedLocation` referencing it.
- `restore_from_trash()` moves it back.

Integration tests in `tests/apply/test_cross_source_apply.py` use one
`FakeSource("gdrive:personal", ...)` and one `LocalFileSystemSource` to
exercise the full mover pipeline with real filesystem effects but zero
network.

### 8.3 Real-API integration tests (skipped in CI unless creds present)

`tests/integration/test_gdrive_real.py` and `test_onedrive_real.py`,
gated on `DC_INTEGRATION_TESTS=1` and the presence of a real token file at
`~/.config/duplicate_cleaner/tokens/gdrive:test.json`. Each creates a
temporary folder in the test drive, uploads a fixture, runs a scan, asserts
the file appears, trashes it via the source, restores it, then hard-deletes
the folder as cleanup. Marked `@pytest.mark.integration` and excluded from
the default `pytest` invocation.

### 8.4 VCR cassettes

For debugging real-API behaviour without repeated calls, tests can be run
once with `VCR_RECORD=all` (using `vcrpy` for Google's httplib2 client and
`respx` for OneDrive's httpx client); cassettes are checked into
`tests/cassettes/`. Cassettes MUST scrub `authorization` headers and
`refresh_token` bodies — a `before_record_response` hook enforces this.

## 10. Rate limits, retries, error taxonomy

`sources/base.py` defines a small exception hierarchy every source raises:

```python
class SourceError(Exception):
    """Base for every failure originating in a Source."""

    source_id: str
    cause: Exception | None

class RateLimitError(SourceError):
    """HTTP 429 or provider-specific throttling."""

    retry_after_seconds: float | None

class AuthExpiredError(SourceError):
    """Token refresh failed and interactive re-auth is required."""

class NetworkError(SourceError):
    """Transient network fault. Callers may retry."""

class PermissionError(SourceError):
    """The account lacks permission for this operation. Non-retryable."""

class NotFoundError(SourceError):
    """The resource does not exist (was permanently deleted, moved
    elsewhere by another client, etc.). Non-retryable."""

class AlreadyRestoredError(SourceError):
    """restore_from_trash() called on a file that isn't in trash."""
```

Retry policy per error type:

| Exception             | Retry?              | How                          |
|-----------------------|---------------------|------------------------------|
| `RateLimitError`      | yes                 | Honor `Retry-After`; if absent, exponential backoff 1→60s, max 5 attempts |
| `NetworkError`        | yes                 | Exponential backoff 1→30s, max 5 attempts |
| `AuthExpiredError`    | no                  | Prompt user; abort scan/apply |
| `PermissionError`     | no                  | Log and skip the entry; continue |
| `NotFoundError`       | no                  | Log and skip; count as "already gone" |
| `AlreadyRestoredError`| no                  | Log per-entry; undo continues |

The `tenacity` retry decorators wrap only the low-level HTTP calls inside
each source. Higher-level code (mover, undo, reconcile) catches
`SourceError` subclasses and translates to user-facing per-entry status.

## 11. Milestones within v0.2

Sequenced strictly. Each is a shippable increment; each has its own
Dev / Review / Security / QA / Docs wave.

### Sub-phase 1 — `LocalFileSystemSource` refactor

Zero behaviour change. Introduces `sources/base.py` + `sources/local.py`.
`FileRecord` gains the six new fields (all defaulted). `scan/walk.py`
unchanged except for the added dataclass fields. Mover / undo pick up a
`sources_by_id` dict but default to `{"local": LocalFileSystemSource(...)}`
when the report has no cloud entries.

Exit gate: **all 110+ existing tests pass unchanged; no new tests required.**
The refactor is purely mechanical.

### Sub-phase 2 — `GoogleDriveSource` (read-only)

Adds `sources/gdrive.py`, `sources/auth/gdrive.py`, `sources/auth/tokens.py`,
`accounts.toml` handling, `dc auth add/remove/list/test` for gdrive,
`dc sources list`, `dc scan --sources` flag. Adds the `cloud_hash_cache`
table + schema migration.

Implements `list_files`, `read_bytes`, `get_metadata`. `move_to_trash` and
`restore_from_trash` raise `NotImplementedError` until sub-phase 3. Reports
include Google Drive members but the mover refuses to trash them.

Exit gate: end-to-end scan with `--sources local,gdrive:personal` produces
a report with Google Drive rows correctly grouped; `cloud_hash_cache` fills
on first run and hits on second run (verified by a cache-hit assertion
test). `--max-cloud-download-mb 0` produces a report where all
cloud-only-bucket files are marked "not-yet-hashed".

### Sub-phase 3 — `GoogleDriveSource` trash + restore

Implements `move_to_trash` + `restore_from_trash`. Manifest schema gets
the three new fields. `dc apply --commit` moves Google files to Drive
trash; `dc undo` restores them.

Exit gate: integration test against a real Google account (opt-in) does a
full round trip; unit tests with mocked SDK cover error paths.

### Sub-phase 4 — `OneDriveSource` (both read + trash)

Adds `sources/onedrive.py`, `sources/auth/onedrive.py`, `dc auth add/...`
for onedrive. Same protocol conformance test suite as Google Drive. Includes
the Business-tenant rejection at `dc auth add` time and the restore-fallback
logic for Personal recycle-bin quirks.

Exit gate: matching to sub-phase 3 but for OneDrive.

### Sub-phase 5 — Cross-source scoring + report + apply integration

Adds `cloud_when_local_exists`, `is_shared_file`, `is_singleton_across_sources`
signals to `score/rules.py`. Extends `report/render.py` to display source
badges and cloud-specific columns (owner, shared indicator). Wires the
mover / undo dispatch so a single manifest can carry mixed-source entries.

Exit gate: end-to-end scenario:
1. `dc scan --sources local,gdrive:personal,onedrive:personal` produces a
   report with cross-source groups.
2. Local + cloud dupe → keeper=local, discard=cloud.
3. `dc apply --commit` on the JSON moves cloud entries to their cloud
   trash bins.
4. `dc undo` restores every cloud entry to its original location.
5. Shared / singleton entries never appear as discards. Verified by
   assertion on the report JSON.
