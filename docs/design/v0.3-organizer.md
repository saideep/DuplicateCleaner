# v0.3 — Organizer Core (`dc organize`)

**Status**: design, ready for implementation
**Scope**: replaces the deferred v0.8/v0.9 organizer with a v0.3 milestone that ships PDF content classification, EXIF event clustering, and cohesion preservation from day one.
**Depends on**: v0.1 (walker, hashing pipeline, apply/undo, SQLite cache), v0.1.1 (bundle handling, archive skips, monitoring). v0.3-g (cross-source) additionally depends on v0.2's `sources/` package.

## 0. Design principles

The organizer is a **read-plan-review-apply** tool with the exact same safety envelope as `dc apply`:

- Discovery is **read-only** — filesystem changes only happen in `dc organize apply --commit`.
- Every move is recorded to a JSON undo manifest before the move happens (same fsync + tmp-rename pattern as `apply/mover.py`).
- Files below the configured confidence threshold go to `Unsorted/`, never to a domain the tool is unsure about.
- Cohesive units (albums, book series, git repos, photo events) move as one — the JSON refuses per-file overrides that split them unless `--split-cohesive-units` is passed.
- The user is not asked to guess. The taxonomy is derived from what the discovery pass actually saw in their data, and every classification carries an auditable signal breakdown that the review UI surfaces.

## 1. Three-phase workflow

The CLI surface adds one command with three sub-commands. All three share the plan file as the single source of truth.

```
dc organize discover <src>... [--sources local,gdrive:personal]
                              [--dest ~/organized]
                              [--plan ~/organize-plan.json]
                              [--ocr]  [--enable-geocode]
                              [--confidence-threshold 0.75]
                              [--event-gap-hours 12]
dc organize review   <plan.json>                # Rich TUI editor (v0.3-a)
dc organize apply    <plan.json> [--commit]
                                 [--split-cohesive-units]
                                 [--runs-dir ~/.local/share/duplicate_cleaner/runs]
dc organize undo     <manifest.json>            # symmetric to `dc undo`
```

### 1.1 `discover`
Walks each source using `scan.walk.iter_files` (already exists), then runs the signal-extractor pipeline described in §2 and the taxonomy classifier in §3. Writes exactly two artifacts:

- `<plan>.json` — machine-readable plan (schema in §8).
- `<plan>.html` — human-readable review report (Jinja2 template, mirrors the existing `report/render.py` pattern).

Zero filesystem changes. Zero writes outside the plan artifacts and the SQLite cache.

### 1.2 `review`
Interactive Rich-based TUI for editing the JSON in place. Actions:
- Rename any proposed folder (updates every file targeted at it).
- Merge two clusters into one folder.
- Split a cluster into two by picking a subset of files.
- Change a single file's destination — with a warning banner if that violates a cohesion group.
- Promote an `Unsorted/` file to one of its top-3 alternatives.

Non-interactive fallback: the user edits the JSON in `$EDITOR`. The apply step re-validates the schema so hand-edits are safe.

### 1.3 `apply`
Dry-run by default (mirrors `dc apply` — same reversed convention). `--commit` creates target folders (mode governed by config, see §9) and moves files. Same undo-manifest layout under `~/.local/share/duplicate_cleaner/runs/<ts>/manifest.json`.

## 2. Discovery signal extraction

For every eligible `FileRecord` yielded by the walker the discovery pass extracts the **union of applicable signals** for that file's type. Each signal is written to a new SQLite table so a rerun can incrementally add signals to files whose stat is unchanged.

### 2.1 SQLite schema (added to `store.py`'s `_SCHEMA`)

```sql
CREATE TABLE IF NOT EXISTS file_signals (
    path        TEXT    NOT NULL,
    source_id   TEXT    NOT NULL DEFAULT 'local',      -- v0.3-g cross-source
    signal_kind TEXT    NOT NULL,                       -- e.g. 'exif.date', 'id3.artist'
    signal_value TEXT   NOT NULL,                       -- string; numeric values stringified
    confidence  REAL    NOT NULL DEFAULT 1.0,
    extracted_ts REAL   NOT NULL,
    PRIMARY KEY (source_id, path, signal_kind)
);
CREATE INDEX IF NOT EXISTS idx_file_signals_path
    ON file_signals(source_id, path);
CREATE INDEX IF NOT EXISTS idx_file_signals_kind
    ON file_signals(signal_kind);

CREATE TABLE IF NOT EXISTS organize_runs (
    scan_id     TEXT PRIMARY KEY,
    started_ts  REAL NOT NULL,
    finished_ts REAL,
    plan_path   TEXT,
    manifest_path TEXT
);

CREATE TABLE IF NOT EXISTS organize_moves (
    scan_id     TEXT NOT NULL,
    source_id   TEXT NOT NULL,
    src_path    TEXT NOT NULL,
    dst_path    TEXT NOT NULL,
    domain      TEXT NOT NULL,       -- HR / Personal / Finances / Photos / ...
    subfolder   TEXT NOT NULL,       -- e.g. 'Payslips/2024'
    confidence  REAL NOT NULL,
    cohesion_group TEXT,             -- non-null → part of a cohesive unit
    committed   INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (scan_id, source_id, src_path),
    FOREIGN KEY (scan_id) REFERENCES organize_runs(scan_id)
);
```

Rows are cached on `(source_id, path, stat)` — a rerun with unchanged stat reuses the signals, matching the existing `get_cached_hash` pattern (`abs(mtime - stored) <= _MTIME_EPS`).

### 2.2 Extractors (`organize/signals/*.py`)

One extractor module per signal family. Every extractor implements:

```python
# organize/signals/base.py
from typing import Protocol

class SignalExtractor(Protocol):
    kind_prefix: str          # e.g. 'exif', 'id3', 'pdf'
    applies_to_suffixes: frozenset[str]

    def extract(self, path: Path, record: FileRecord) -> list[Signal]: ...

@dataclass(frozen=True)
class Signal:
    kind: str                 # 'exif.date_original', 'id3.artist', ...
    value: str
    confidence: float = 1.0
```

The signals harvested per family:

| Family | Files | Signals | Library |
|---|---|---|---|
| Universal | all | `mime.top`, `mime.sub`, `size`, `mtime.year`, `mtime.month`, `path.token.*` | stdlib `mimetypes` (core); `python-magic` optional |
| Music | `.mp3 .m4a .flac .wav .ogg .opus` | `id3.artist`, `id3.album`, `id3.track`, `id3.year`, `id3.genre`, `id3.disc`, `id3.albumartist` | `mutagen` |
| Photo | `.jpg .jpeg .heic .png .raw .tiff .cr2 .nef .arw .dng` | `exif.date_original`, `exif.make`, `exif.model`, `exif.gps.lat`, `exif.gps.lon` | `Pillow.ExifTags` (core, already dep) + `piexif` (GPS only, optional-extra) |
| Video | `.mp4 .mov .mkv .avi .m4v` | `video.create_date`, `video.gps.lat`, `video.gps.lon`, `video.duration_s` | `hachoir` |
| PDF | `.pdf` | `pdf.info.title`, `pdf.info.author`, `pdf.info.producer`, `pdf.info.creation_date`, `pdf.info.keywords`, `pdf.text.first_page` (truncated to 4 KB), `pdf.class.<label>` (see §5) | `pikepdf` + `pdfplumber` |
| Office | `.docx .pptx .xlsx` | `office.title`, `office.author`, `office.created`, `office.category` | `python-docx`, `python-pptx`, `openpyxl` — optional-extra `[docs]` |
| Filename | all | `fname.date`, `fname.issuer`, `fname.keyword.<label>`, `fname.seqno` | regex only |
| Git | dirs during a second-phase walk | `git.repo_name`, `git.remote_origin` | subprocess `git rev-parse --show-toplevel` |

`path.token.*` is a coarse tokenization of the path components (splitting on `/`, `_`, `-`, camelCase) — feeds the filename pattern matcher without re-walking the string in every rule.

### 2.3 Filename pattern regexes (in `organize/signals/filename.py`)

- Date: `\b(19|20)\d{2}[-_./]?(0[1-9]|1[0-2])[-_./]?(0[1-9]|[12]\d|3[01])\b` — canonicalize to `YYYY-MM-DD`.
- Compact date: `\b(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\b`.
- Numbered sequence: `^\s*(0?\d{1,3})\s*[-._]\s*` or `IMG_(\d+)`, `DSC(\d+)`, `MVI_(\d+)` — feeds photo-burst detection.
- Vendor / issuer: matched against a static dictionary loaded from `organize/data/issuers.yml` (see §3.1).
- Keyword tags: `invoice`, `statement`, `payslip`, `receipt`, `offer`, `w2`, `1099`, `passport`, `visa`, `insurance`, `policy` — case-insensitive substring on tokens.

The static vocabulary is a plain YAML file shipped with the package (`src/duplicate_cleaner/organize/data/`). Users can extend it via `~/.config/duplicate_cleaner/organize.toml` with an `[extra_vendors]` table — merged at load, never mutated on disk by the tool.

## 3. Domain taxonomy — rule set

The classifier consumes the union of signals for a file and produces a `Classification`:

```python
# organize/classify.py
@dataclass(frozen=True)
class Classification:
    domain: str                 # 'HR' | 'Personal' | 'Finances' | 'Photos' |
                                # 'Videos' | 'Work' | 'Projects' | 'Media' | 'Unsorted'
    subfolder: PurePosixPath    # relative, e.g. 'Payslips/2024'
    confidence: float           # 0..1
    signals_fired: list[FiredRule]
    alternatives: list[tuple[Classification, float]]  # top-2 alt classifications

@dataclass(frozen=True)
class FiredRule:
    rule_id: str
    weight: float
    matched_signal_kinds: list[str]
```

### 3.1 Rule shape

Rules are declarative in a module-level Python list (`organize/rules.py`) and gain nothing from being data-only, since predicates can inspect any signal. Each rule:

```python
@dataclass(frozen=True)
class Rule:
    id: str
    domain: str
    subfolder_template: str          # Jinja-lite: '{year}', '{vendor}', '{artist}'
    predicates: list[Predicate]      # ALL must return a non-zero score
    precedence: int                  # higher wins on tie
    combine: Literal["sum", "max"] = "sum"

class Predicate(Protocol):
    def score(self, signals: SignalBag) -> tuple[float, list[str]]: ...
    # returns (contribution, [signal_kinds_matched])
```

`SignalBag` is a per-file dict of `signal_kind -> value` with helpers like `has("id3.artist")`, `year_hint()` (checks `pdf.info.creation_date`, `exif.date_original`, `fname.date`, `mtime.year` in order), `first_page_text()`, `path_tokens()`.

### 3.2 The rule catalog (v0.3 initial set)

Format: `id | domain | subfolder | predicates | precedence | notes`.

**HR domain**

- `hr.payslip | HR | Payslips/{year} | fname_kw("payslip|salary|pay.slip|pay.stub") 0.5 OR pdf_class("payslip") 0.9 | 90 | year from pdf date > fname date > mtime`
- `hr.offer | HR | OfferLetters/{year}-{employer} | fname_kw("offer|hire|welcome|joining") 0.4 OR pdf_class("offer_letter") 0.9 | 85 | employer from top-3 PDF lines`
- `hr.tax | HR | Tax/{year} | fname_kw("w2|1099|w-2|form.16|itr|1040") 0.7 OR pdf_class("tax_form") 0.9 | 88 |`
- `hr.employment | HR | Employment/{year} | pdf_class("employment_misc") 0.6 OR fname_kw("nda|noc|contract.employment") 0.6 | 70 | fallback within HR`

**Personal domain**

- `personal.ids | Personal | IDs | pdf_class("id_document") 0.9 OR fname_kw("passport|driver.license|pan|aadhaar|ssn|voter.id") 0.7 | 85 | no {year} — IDs live in a flat folder`
- `personal.insurance | Personal | Insurance/{year} | pdf_class("insurance") 0.85 OR fname_kw("insurance|policy|premium") 0.5 | 80 |`
- `personal.legal | Personal | Legal | fname_kw("contract|agreement|notary|will|poa") 0.6 OR pdf_class("legal") 0.8 | 75 |`

**Finances domain**

- `fin.receipt | Finances | Receipts/{year}/{vendor} | pdf_class("receipt") 0.9 OR fname_kw("receipt|order.confirm") 0.6 | 82 | vendor from PDF header or filename issuer dict`
- `fin.statement | Finances | Statements/{year}/{institution} | pdf_class("bank_statement") 0.9 OR fname_kw("statement|account.summary") 0.5 | 82 |`
- `fin.invoice | Finances | Invoices/{year} | pdf_class("invoice") 0.85 OR fname_kw("invoice|bill|inv.no") 0.6 | 78 |`
- `fin.investment | Finances | Investments/{year} | pdf_class("investment") 0.85 OR fname_issuer(brokerages) 0.6 | 78 |`

**Photos / Videos**

- `photo.event | Photos | {year}/{event_folder} | media_photo() 0.5 AND event_cluster_present() 0.4 | 95 | event_folder from event-clustering (§4)`
- `photo.month | Photos | {year}/{yyyy_mm} | media_photo() 0.7 | 60 | fallback for isolated photos`
- `video.event | Videos | {year}/{event_folder} | media_video() 0.5 AND event_cluster_present() 0.4 | 95 |`
- `video.month | Videos | {year}/{yyyy_mm} | media_video() 0.7 | 60 |`

**Work**

- `work.project | Work | {year}/{client_or_project} | office_doc() 0.5 AND path_token_hint("Client|Project|Proposal|Deck") 0.4 | 70 |`
- `work.year | Work | {year} | office_doc() 0.7 | 55 |`

**Projects**

- `proj.git | Projects | {repo_name} | is_inside_git_repo() 1.0 | 99 | forced by cohesion, never split`

**Media**

- `media.music | Media | Music/{artist}/{album} | id3_complete(artist, album) 0.9 | 95 | cohesion via album`
- `media.books | Media | Books/{topic} | ext(".pdf",".epub") 0.4 AND topic_cluster() 0.5 | 78 | topic set is config-extendable`

**Unsorted (implicit)**

- No rule fires above the threshold (see §7). The classifier returns `Unsorted/<domain-guess>` if the best-scoring rule got `confidence >= 0.4` — otherwise flat `Unsorted/`.

### 3.3 Precedence and tie-breaking

The classifier computes a score for every rule and:

1. Selects the rule with the highest score.
2. On tie (within 1e-6): higher `precedence` wins.
3. On still-tie: the rule with the more specific subfolder template (measured by number of `{}` placeholders resolved) wins.
4. Still-tie: alphabetical `rule_id` — deterministic across runs.

Alternatives (the 2nd-best and 3rd-best scoring rules) are stored on the plan entry so `dc organize review` can offer them.

### 3.4 Vendor / institution / employer extraction

Extracted from the union of:
- PDF top-3 lines (`pdf.text.first_page` sliced by newline).
- Filename tokens matched against `issuers.yml`.
- Static institution list for statements: `Chase, Wells Fargo, Bank of America, Citi, Discover, HDFC, ICICI, SBI, Amex, Capital One`.
- Static vendor list for receipts: `Amazon, Uber, DoorDash, Whole Foods, Home Depot, Costco, Target, Walmart, Apple, Best Buy`.
- Static brokerage list: `Vanguard, Fidelity, Charles Schwab, Robinhood, E*TRADE, Merrill, TD Ameritrade`.

Match order: exact case-insensitive substring in first PDF line → tokenized filename → subsequent lines. First match wins. If no vendor can be pinned, the subfolder gets `UnknownVendor` and the entry drops below the confidence threshold (goes to Unsorted).

## 4. Event clustering for photos/videos (`organize/cluster.py`)

Input: every file with a resolvable capture timestamp (`exif.date_original` for photos, `video.create_date` for videos, fallback to `mtime` only if none of those exist AND `path.token.date` matches — otherwise the file is dropped from clustering and falls back to the monthly rule).

### 4.1 Algorithm

```python
def cluster_events(
    items: list[MediaItem],
    *,
    gap_hours: float = 12.0,
    gps_km_threshold: float = 50.0,
    min_event_photos: int = 5,
) -> list[Event]:
    """Time-gap split → optional GPS outlier split → naming."""
    items.sort(key=lambda i: i.captured_at)
    events: list[Event] = []
    current: list[MediaItem] = []
    prev_ts: float | None = None
    for item in items:
        if prev_ts is None or (item.captured_at - prev_ts) < gap_hours * 3600:
            current.append(item)
        else:
            events.append(_close_event(current))
            current = [item]
        prev_ts = item.captured_at
    if current:
        events.append(_close_event(current))
    events = _split_by_gps_outliers(events, gps_km_threshold)
    return [e for e in events if len(e.items) >= min_event_photos] + \
           [_synthesize_monthly(e) for e in events if len(e.items) < min_event_photos]
```

### 4.2 GPS outlier split

Only runs on events where ≥ 50 % of items have GPS. Computes centroid as the arithmetic mean of lat/lon (fine at event scale; not projecting because we only need a threshold), then flags items whose `geodesic(centroid, item)` > `gps_km_threshold` as outliers. Outliers form a sub-event; if the sub-event still has < `min_event_photos` items they drop back to the monthly fallback.

### 4.3 Naming

- Single-day event: `2024-06-15`.
- Multi-day event: `2024-06-15_to_2024-06-18`.
- With `--enable-geocode`: append `_<Locality>` from Nominatim reverse-geocode of the centroid — `2024-06-15_to_2024-06-18_Bali_Indonesia`. Nominatim usage policy: max 1 req/sec, always send `User-Agent: duplicate-cleaner/0.3 (+github.com/user/repo)`. All results cached in `file_signals` under `gps.geocode` keyed on rounded (lat, lon) to 3 dp.

### 4.4 Trade-offs (recorded here so we don't relitigate)

- **Offline default**: date-only names. No new external dep beyond `geopy`, and even that is only imported when the flag is set.
- **Online opt-in**: `--enable-geocode` adds ~1 s of wall time per unique centroid (bounded by the rate-limit sleep). For 20 events that's 20 s — acceptable.
- **Never fail-closed on geocode**: if Nominatim errors, fall back to the date-only name and log a warning. Discovery never blocks on a network dep.

## 5. PDF content classification (`organize/pdf_classify.py`)

For each PDF the discovery pass:

1. Reads `Info` dict via `pikepdf` — cheap, always available.
2. Extracts first-page text via `pdfplumber` — bounded to first page, max 8 KB truncation for very large first pages.
3. If `--ocr` is set AND `pdfplumber` returned < 100 chars AND `pytesseract` is importable: run OCR on the first-page rasterization. This is opt-in because OCR is 10-50× slower than text extraction.

### 5.2 Score → confidence

```
raw_score(class) = Σ (weight_i if keyword_i present else 0)
max_score(class) = Σ weight_i
confidence(class) = raw_score(class) / max_score(class)
```

Threshold 0.6 to emit `pdf.class.<label>` signal with `confidence = raw/max`. If two classes exceed the threshold, both are recorded but only the highest feeds the classifier's rule; the second is written to the plan's `alternatives` field.

### 5.3 Year, vendor, employer extraction from PDF

- **Year**: `pdf.info.creation_date` (parsed via `pikepdf.Name('/CreationDate')` string decoder) → first date match in first-page text → filename date → `mtime.year`.
- **Vendor / institution / employer**: the top 3 non-empty lines of the first page (usually the letterhead). Match against the static dictionaries in §3.4. Falls back to filename tokens.

## 6. Cohesion preservation (`organize/cohesion.py`)

A cohesive unit is a set of files that must move together. Detection is per-directory:

### 6.1 Detection

For every directory encountered by the walker, compute a cohesion signal per (candidate) domain. A directory is cohesive if:

- **Music album**: ≥ 80 % of audio files inside share the same `(id3.albumartist or id3.artist, id3.album)` tuple. Cohesion key: `music:{artist}/{album}`.
- **Book series**: ≥ 80 % of PDFs share (a) the same top-1 topic classification OR (b) a common filename prefix of ≥ 4 characters AND the same `pdf.info.author`. Cohesion key: `books:{topic}` or `books:{prefix}`.
- **Photo/video event**: ≥ 80 % of media files fall into the same event cluster as detected in §4. Cohesion key: `event:{event_id}`.
- **Photo burst**: ≥ 5 sequential filenames (`IMG_1234, IMG_1235, ...`) inside a 10-minute window. Cohesion key: `burst:{event_id}` — treated as a sub-cohesion of an event.
- **Git project**: directory contains `.git/`, `package.json`, `Cargo.toml`, `pyproject.toml`, `go.mod`, `pom.xml`, or `.hg/`. Cohesion key: `project:{repo_name}`. Detection is atomic — even sibling files without those markers move along.

An individual file can belong to **at most one** cohesion group; a music file inside a git repo picks the git cohesion (project trumps album because splitting a repo is worse than splitting an album).

### 6.2 Enforcement

Every plan entry that's inside a cohesive unit carries `cohesion_group: str` in the JSON. `apply`:

1. Loads the plan.
2. Groups entries by `cohesion_group`.
3. For each group, verifies all members target the same destination folder.
4. If any per-file `destination` in the group differs and `--split-cohesive-units` was not passed → raises `ApplyError` listing the violating entries and exits before any move.

Reason for the strict check: the cohesion invariant is the promise the user is relying on. Silently accepting a mid-move split at commit time would make undo confusing.

### 6.3 Test-case fixtures (owned by QA agent)

`tests/fixtures/organize/` must contain:
- `album/` — 10 mp3 files, same album/artist ID3, no track numbers in filename.
- `book-series/` — 5 PDFs, filename prefix `Learning Python -`, shared author.
- `project/` — bare `.git/` directory plus `README.md`, `pyproject.toml`, and a couple of source files.
- `phone-photos/` — 20 `.jpg` files spanning three days, EXIF timestamps within a single trip.
- `burst/` — 8 `.jpg` files named `IMG_0001.JPG..IMG_0008.JPG` timestamped ~1 min apart.
- `mixed/` — a directory with 5 payslip PDFs, 3 misc PDFs, 2 photos — should NOT be flagged cohesive (no single domain > 80 %).

## 7. Confidence gating and Unsorted

- Every classified file has `confidence ∈ [0, 1]`.
- `organize_confidence_threshold` (config, default `0.75`): below → `Unsorted/`.
- If the top classifier still had confidence ≥ 0.4, the destination is `Unsorted/<domain-guess>/` (e.g. `Unsorted/Finances/`) — helps the user triage in bulk during review.
- Otherwise: flat `Unsorted/`.
- Every Unsorted entry carries `alternatives` (top-3 candidate destinations) in the JSON. The review UI presents these as a dropdown.

### 8.2 HTML view (v0.3-f)

Template: `report/templates/organize-plan.html.j2`. Sections top-to-bottom:

1. **Summary bar** — total files, files-per-domain badge counts, sum of source bytes, sum of destination bytes (they're equal at organize time — this is not a delete tool — but shown for symmetry with `dc apply`).
2. **Proposed tree** — collapsed tree view of `dest_root`, expandable per folder. Each folder header shows `count · size`.
3. **Per-file rows** (revealed on expand) — src path, confidence pill, top signals, cohesion badge if present, dropdown of top-3 alternatives.
4. **Unsorted section** — highlighted with `background: #fff3cd`. Same row shape but with the alternatives dropdown pre-open.
5. **Cohesive units panel** — separate list, one row per group, "expand" reveals member paths.

Editing HTML doesn't mutate JSON (per the existing `dc scan` contract — HTML is a view, JSON is the source of truth). The dropdown pattern is prepared for a v0.3-f enhancement where a small JS shim posts choices to a local `dc organize serve` process, but that's out of scope for the initial ship.

### 8.3 Rich TUI (v0.3-a)

Keyboard-driven interactive editor. Ships in v0.3-a alongside discover so the JSON is editable from day one. Commands:

- `n` / `p` — next / prev entry (or group with `N`/`P`).
- `d` — change destination via a fuzzy-finder over all folders in the current plan + a free-text option.
- `1..3` — pick alternative 1/2/3 for this entry.
- `m` — merge current cluster with another (prompts for target).
- `s` — split a cluster (prompts for which files to move out).
- `x` — mark cluster as "leave in place" (removes all its entries).
- `!` — override cohesion for one entry (still refuses to commit without `--split-cohesive-units` on apply).
- `w` — write plan JSON and exit.

## 9. Apply, folder creation, collision handling, undo

### 9.1 Directory creation

`apply --commit`:
- Groups moves by destination folder.
- For each folder: `os.makedirs(dest, mode=0o755, exist_ok=True)` — matches the user's umask on macOS by default. Rationale: 0o700 would silently break shared-directory workflows (e.g. `/Volumes/Family/Photos`), and `dc apply` for dedup doesn't restrict permissions. Config knob `organize_dir_mode` for users who want `0o700`.
- Failing directory create is fatal — the run aborts before moving anything.

### 9.2 Collision policy

If `<dest>/<filename>` already exists at move time:
1. If the existing file hashes identical to the source (BLAKE3, streamed) → skip the move, log `already-present-at-dest` in the manifest, do not delete the source (this is `organize`, not `dedup` — dedup happens separately upstream in the workflow).
2. Otherwise: append `_<hash8>` (first 8 hex of source's BLAKE3) to the stem: `receipt.pdf` → `receipt_a3f1b2c9.pdf`. Log the collision in the manifest under `collisions[]`.

### 9.3 Move implementation

- Same volume: `os.rename(src, dst)` — atomic on POSIX.
- Cross-volume (external drive → internal home): `shutil.copy2(src, dst)` + fsync + `send2trash(src)`. Rationale: never `os.remove` while organizing, in case a hash mismatch surfaces post-copy. The undo path (§9.5) knows to restore from Trash.

### 9.4 Manifest schema

```jsonc
{
  "version": "0.3.0",
  "scan_id": "...",
  "created_at": "20260905T170000Z",
  "roots": ["/Users/vaannada/Downloads"],
  "dest_root": "/Users/vaannada/organized",
  "entries": [
    {
      "source_id": "local",
      "src_path": "/Users/.../payslip_march_2024.pdf",
      "dst_path": "/Users/vaannada/organized/HR/Payslips/2024/payslip_march_2024.pdf",
      "size": 214532,
      "mtime": 1710519600.0,
      "hash": "blake3:...",
      "cohesion_group": null,
      "collision_renamed_to": null,
      "cross_volume": false,
      "trashed_at_path": null
    }
    // ...
  ]
}
```

### 9.5 Undo (`dc organize undo <manifest>`)

Symmetric to `apply/undo.py`. For each entry:
- If `cross_volume=false`: `os.rename(dst, src)` — restores the atomic in-place move.
- If `cross_volume=true`: recover source from the Trash entry (`trashed_at_path` or `_locate_by_basename_and_size` fallback), then delete the dst copy after verifying its hash matches.

Reuses `apply.undo._locate_by_basename_and_size` and `apply.mover._verify_unchanged` — enough shared behavior that the undo module should split its trash-finding helpers into `apply/trash_locator.py` in the same CR that lands v0.3-b.

## 10. Interaction with dedup

The end-to-end workflow (from the plan) is:
```
dedup local → dedup cross-source → organize → migrate cloud
```

**Recommendation: soft warning by default, hard refusal via config.**

Concrete policy for `dc organize discover`:

- On start, query `store.groups` for the most recent scan.
- If the most recent scan has any `group_members` where `is_proposed_keeper = 0 AND is_informational = 0` (i.e. proposed discards) AND no matching `dc apply` run exists within the last hour: emit a warning to stderr:
  ```
  Warning: pending duplicate groups from scan 2026-09-05T15:22 (found 42 discardable files).
           Organize runs best AFTER dedup. Consider: `dc apply ~/dc-report/report.json`.
           Continue anyway? [y/N]
  ```
- The user can pass `--skip-dedup-check` to suppress the prompt in scripts.
- A config knob `enforce_dedup_ordering: bool = false` (default `false`) upgrades the warning to a hard refusal. Turned on, the user gets a `dc apply` command in the error message.

**Rationale for soft-by-default**: the user may have legitimate reasons to organize before deduping (e.g. adding a fresh external drive whose contents are all new — no dedup value to be had). A hard refusal is annoying for those cases. The warning path is enough to prevent the accidental case.

## 11. Dependency changes (pyproject.toml)

Core (added to base install):
- `mutagen>=1.47,<2` — ID3 read; small, pure Python, no system deps.
- `pikepdf>=9,<10` — PDF Info dict; already-good C library, wheels for Apple Silicon.
- `hachoir>=3.3,<4` — video metadata; pure Python, no ffmpeg dep.
- `geopy>=2.4,<3` — only for `--enable-geocode`. Small enough to include in core; the network usage is opt-in.

Optional-extras:
- `[docs]`: `python-docx>=1.1,<2`, `python-pptx>=1.0,<2`, `openpyxl>=3.1,<4`. Users without Office files skip these ~15 MB.
- `[gps]`: `piexif>=1.1,<2`. Pillow already carries `Image.getexif().get_ifd(GPSIFD)` on ≥ 10.4 which handles most cases; `piexif` is a fallback for the corner cases where Pillow can't parse older EXIF blocks.
- `[ocr]`: `pytesseract>=0.3,<0.4`. Requires system `tesseract` (Homebrew). Only imported behind `--ocr`.
- `[mime]`: `python-magic>=0.4,<0.5`. `mimetypes` from stdlib is the primary path; `python-magic` is a strict upgrade for content-sniffed MIME.

**Stdlib `mimetypes` is core; python-magic is optional.** Rationale: adding a compiled C dependency (`libmagic`) as a hard requirement on Mac mini would force users to `brew install libmagic` before `uv sync` works. The signal quality delta between `mimetypes` and `python-magic` is small enough that the setup friction isn't worth it in the default path.

### 13.1 Discover trace

The walker yields records. For each:

- `payslip_march_2024.pdf`:
  - `fname.keyword.payslip` (0.5)
  - `pdf.info.creation_date = "D:20240315..."` → `year = 2024`
  - `pdf.text.first_page` matches `Gross Pay, Net Pay, Employee ID, YTD, Deductions` → `payslip` score 3+3+2+1+2 = 11 / max 15 = **0.73** → `pdf.class.payslip` (0.73)
  - Rule `hr.payslip` fires: max(0.5, 0.73·0.9) → **0.66** — below threshold 0.75.
  - Actually the combined predicate scores `0.5 + 0.66 = 1.16` clamped to 1.0 (sum rule); the classifier normalizes by max possible → **confidence = 0.83**.
  - Destination: `HR/Payslips/2024/payslip_march_2024.pdf`.
- Other two payslips: same rule, same folder.
- `Amazon_receipt_Order_112-4839.pdf`:
  - `fname.keyword.receipt` (0.6), `fname.issuer.Amazon` (0.6).
  - `pdf.class.receipt` fires above 0.6 (Order #, Subtotal, Total, Payment Method) → confidence ~0.8.
  - Rule `fin.receipt` picks vendor `Amazon`, year 2024. Destination: `Finances/Receipts/2024/Amazon/Amazon_receipt_Order_112-4839.pdf`.
- 50 Bali photos:
  - EXIF date + GPS on all of them.
  - Event clustering: single event `2024-06-15_to_2024-06-18` (all within 4 days, gap < 12 h between successive shots, GPS all within 30 km of centroid).
  - Cohesion: directory `vacation-bali/` has 100 % of files in the same event → **cohesion group `event:2024-06-15_bali`**.
  - Destination: `Photos/2024/2024-06-15_to_2024-06-18/` (offline mode; with `--enable-geocode` → `Photos/2024/2024-06-15_to_2024-06-18_Bali_Indonesia/`).
- 7 FLAC tracks:
  - `id3.artist=Miles Davis`, `id3.album=Kind of Blue` on all seven.
  - Directory `kind-of-blue/` has 100 % of files sharing `(artist, album)` → **cohesion group `music:Miles Davis/Kind of Blue`**.
  - Rule `media.music` fires. Destination: `Media/Music/Miles Davis/Kind of Blue/`.
- `random-download.pdf`:
  - No filename keywords match.
  - PDF class scores: `bank_statement=0.05, invoice=0.03, receipt=0.10` — nothing above 0.6.
  - Best classification confidence ~0.2. Below `Unsorted/<domain>` fallback threshold too (0.4).
  - Destination: `Unsorted/random-download.pdf`. Alternatives list contains the top-3 rules that scored anything, so the reviewer can promote it.

## 14. Open questions / follow-ups for later milestones

- **Learning loop** (v0.7-style adaptive weights) for the organizer's rule contributions — deferred until we have real user overrides to learn from.
- **Duplicate filenames across cohesion groups** — if two different Kind of Blue rips live in different folders, both cohesion groups target `Media/Music/Miles Davis/Kind of Blue/` and collide. v0.3 uses the `_<hash8>` suffix; v0.4 may add a per-album quality score (bitrate, format) so the better copy wins.
- **Reverse-geocode caching across scans** — currently per-scan cache; extending it to `file_signals` under `gps.geocode` would make repeat organize runs free of network calls. Documented above but flagged as an optimization, not a blocker.
- **HTML → JSON write-back** — punting to v0.3-f; today the JSON is the truth and HTML is a view.
