# v0.2 Sub-phase 5 — Cross-Source Path Validation, Scoring, and Apply/Undo Integration

Status: design, ready for Dev implementation.
Scope: closes the two flagged-latent items from AUDIT_LOG pass 5 & 6
(`Path("gdrive:x://foo")` in `_validate_report_paths`, `LocalFileSystemSource.restore_from_trash`
bypassing undo rails) and delivers the sub-phase 5 exit gate: mixed-source
reports flow end-to-end through `dc apply --commit` and `dc undo`, cross-source
scoring signals land in `score/rules.py`, and every invariant in `AUDIT_LOG.md`
survives.

This document is a Design→Dev contract. Every function signature, JSON field,
schema-version marker, error class, and stage boundary below is intentional.
The Dev agent may refine internal helpers but MUST land the public shapes and
on-disk artifacts exactly as described.

## 1. The problem in concrete terms

Sub-phase 2 shipped `GoogleDriveSource` and it writes records like

```python
FileRecord(
    path=Path("gdrive:personal://My Drive/Photos/2024/Bali.jpg"),
    ...,
    source_id="gdrive:personal",
    cloud_file_id="1AbCdEf...",
    etag="1AbCdEf...:2024-06-01T12:00:00Z",
)
```

`Path("gdrive:personal://My Drive/Photos/2024/Bali.jpg")` is **relative** on
POSIX — the leading `gdrive:personal:` is a path component, not a scheme.
POSIX `pathlib.Path` collapses adjacent slashes, so on disk the string is
actually `gdrive:personal:/My Drive/Photos/2024/Bali.jpg` (see AUDIT_LOG sub-phase 2
"Notes for review"). Consequences:

- `resolve_for_check(Path("gdrive:personal://..."))` in `paths.py:87` calls
  `path.resolve(strict=False)`, which joins the relative path to `os.getcwd()`.
  The result is something like `/Users/vaannada/Work/Projects/CODE/DuplicateCleaner/gdrive:personal:/My Drive/...`
   — meaningless, but a real `Path`.
- `validate_not_excluded(resolved)` mostly passes (the joined path is not
  inside `/System`, `~/Library`, etc.). Occasionally passes into cwd-adjacent
  EXCLUDED_ROOTS by accident.
- `is_within(resolved, root)` in `_validate_report_paths` fails silently
  because none of the report's local `roots` contain `cwd/gdrive:personal:/...`
  — so every cloud discard would be **rejected** with a "Refusing to touch path
  outside the recorded scan roots" error. That would mask the actual defect
  (cloud entries can't be validated by local rules) as a benign "no cloud
  discards were applied".
- The same shape exists in `restore_from_manifest` via
  `validate_not_excluded(original_path)` at `undo.py:279`.

`LocalFileSystemSource.restore_from_trash` (finding from pass 5) has an
adjacent problem: it calls `apply.undo.local_restore`, which runs
`validate_restore_paths`. Pass 5 flagged that `local_restore` did NOT run the
rails when invoked directly from the source method — it was fixed in the
sub-phase 1 update (see `sources/local.py:117-124`), but the shared validator
`validate_restore_paths` still assumes a local `original_path`. Sub-phase 5
must ensure cloud entries never reach `local_restore` at all.

Every fix in this doc closes both landmines from a single mechanism:
**source-id dispatch happens BEFORE any path validator runs**.

## 2. Path scheme design — decision

**Ranked evaluation** (criteria: correctness, schema migration cost,
dispatch overhead, review-ability, alignment with existing code):

| Alt | Correctness | Schema cost | Dispatch overhead | Reviewability |
|-----|-------------|-------------|-------------------|---------------|
| A. Scheme-prefix opaque strings + `CloudRef` | High | High (new type) | Type-dispatched | Excellent |
| B. Typed `Location` union | Highest | Highest (union everywhere) | Type-dispatched | Excellent |
| C. `<source_id>://` in `Path` + `is_cloud_path`/`parse_source_path` helpers | High | Low (add fields) | Predicate-dispatched on `source_id` | Good |
| D. Split `apply_local` / `apply_cloud` | Local: high; cloud: high | Low | No dispatch (two codepaths) | Poor (DRY violation for undo) |

### Recommendation: **Alternative C**

The `FileRecord.source_id` field already exists (sub-phase 1). Every
`GoogleDriveSource` record carries a `source_id != "local"` today. The dispatch
is therefore a **field lookup, not a string-parse**: mover/undo look at
`entry["source_id"]`, and if it is not `"local"` the entry is a cloud entry.
The `Path` object is retained purely for **display and manifest replay** —
never resolved, never joined, never validated as a filesystem path.

Justification vs alternatives:
- **A/B** are architecturally cleaner but demand cascading changes across
  `FileRecord`, `ReportMember`, `ReportGroup`, `ScoredMember`, every mover /
  undo / renderer / test that constructs one of these — an order of magnitude
  more surface than C, for no correctness gain. Sub-phase 6 (organizer,
  v0.3) has stated tolerance for a `Location` refactor later if it becomes
  load-bearing.
- **D** duplicates the manifest reader/writer and the `_validate_report_paths`
  root-check helper, and forces `dc undo` to load a manifest twice or split
  it. Mixed manifests (some local, some cloud) become impossible to reason
  about.
- **C**'s risk — string-based dispatch fragility — is mitigated by:
  1. Never parsing the `Path` string. `source_id` is the only dispatch key.
  2. A single `is_cloud_entry(entry) -> bool` helper (returns
     `entry["source_id"] != "local"`) used everywhere.
  3. A regression test that constructs a manifest entry with
     `source_id="gdrive:personal"` and asserts it never enters
     `resolve_for_check`.

Cross-cutting invariant restated: **the `pathlib.Path` on a cloud FileRecord
is a human-readable label. Nothing in `apply/` or `paths.py` may call
`.resolve()`, `.exists()`, `.stat()`, or `.parent` on it.**

### 3.3 Backward compatibility contract

- **Reader** (`load_report`, `restore_from_manifest`) MUST accept a file with
  no `version` / `manifest_version` and treat it as v0.1.1.
- **Reader** MUST default missing `source_id` to `"local"`.
- **Reader** MUST reject any `source_id` that is neither `"local"` nor
  present in `AccountsRegistry.list()` — a stale manifest referencing an
  account the user has since removed cannot dispatch safely.
- **Writer** always writes the new fields (with `null` where absent) and the
  version marker, so files written by v0.2 look identical whether the report
  was originally local-only.

## 4. Validation logic

### 4.1 New helpers in `sources/base.py`

```python
def is_cloud_entry(entry: object) -> bool:
    """True if the entry (report member OR manifest row) refers to a cloud file."""
    # Accepts a Pydantic ReportMember or a dict — sub-phase 5 callers.
    sid = getattr(entry, "source_id", None) or (
        entry.get("source_id", "local") if isinstance(entry, dict) else "local"
    )
    return sid != "local"


# Per-provider cloud_file_id shape. Kept intentionally loose — providers may
# rotate their id formats. Presence + printable-ASCII + length bound is the
# safety property; exact regex fit is not.
_CLOUD_FILE_ID_RE: dict[str, re.Pattern[str]] = {
    "gdrive": re.compile(r"^[A-Za-z0-9_-]{10,200}$"),
    "onedrive": re.compile(r"^[A-Za-z0-9!._~-]{10,200}$"),
}


def validate_cloud_entry(
    entry: dict,
    *,
    authorized_source_ids: set[str],
) -> None:
    """Raise ApplyError/UndoError-shaped ValueError on any cloud-entry defect.

    Callers wrap the ValueError in their own exception type — this helper is
    shared between mover and undo so poisoned-manifest rules are enforced
    exactly once.
    """
    sid = entry["source_id"]
    if sid not in authorized_source_ids:
        raise ValueError(
            f"unknown source_id {sid!r}; not in AccountsRegistry "
            f"({sorted(authorized_source_ids)})"
        )
    cfid = entry.get("cloud_file_id")
    if not isinstance(cfid, str) or not cfid:
        raise ValueError(f"cloud entry has no cloud_file_id: {entry!r}")
    provider = sid.split(":", 1)[0]
    pattern = _CLOUD_FILE_ID_RE.get(provider)
    if pattern is not None and not pattern.match(cfid):
        raise ValueError(
            f"cloud_file_id {cfid!r} does not match {provider} shape"
        )
    etag = entry.get("etag")
    if not isinstance(etag, str) or not etag:
        raise ValueError(
            "cloud entry missing etag (required for pre-trash drift check)"
        )
```

Google-native mime filtering stays in `GoogleDriveSource._item_to_record` at
scan time (already implemented). Sub-phase 5 does not re-check mimeType at
apply time — by construction a Google-native file never reaches the report.

### 4.2 New `_validate_report_paths`

Pseudocode (replaces `apply/mover.py:52-114`):

```python
def _validate_report_paths(
    report: Report,
    authorized_source_ids: set[str],
) -> list[Path]:
    if report.discover:
        raise ApplyError("...discover-mode input...")
    if not report.roots:
        raise ApplyError("...no roots...")
    for r in report.roots:
        try:
            validate_scan_root_candidate(Path(r))
        except ValueError as e:
            raise ApplyError(f"report.roots entry rejected — {e}") from e
    resolved_roots = [resolve_for_check(Path(r)) for r in report.roots]

    for g in report.groups:
        for m in g.members:
            if m.is_proposed_keeper or m.is_informational:
                continue

            # Cross-cutting: singleton-never-a-discard.  A member marked
            # is_singleton_across_sources is guaranteed informational by the
            # scorer, but re-assert here — belt-and-suspenders.
            _assert_not_singleton(m)

            if m.source_id == "local":
                # Existing v0.1.1 rails — unchanged.
                path_str = str(m.path)
                if is_virtual_archive_path(path_str):
                    raise ApplyError(f"archive-member path: {path_str}")
                resolved = resolve_for_check(Path(m.path))
                try:
                    validate_not_excluded(resolved)
                except ValueError as e:
                    raise ApplyError(f"excluded: {e}") from e
                if not any(is_within(resolved, r) for r in resolved_roots):
                    raise ApplyError(
                        f"outside scan roots: {resolved}"
                    )
            else:
                # Cloud entry — bypass local rails, enforce cloud rails.
                try:
                    validate_cloud_entry(
                        m.model_dump(),
                        authorized_source_ids=authorized_source_ids,
                    )
                except ValueError as e:
                    raise ApplyError(f"cloud entry rejected: {e}") from e
                if m.is_shared:
                    raise ApplyError(
                        f"shared cloud file cannot be a discard: {m.path}"
                    )
    return resolved_roots
```

Key properties:
- Local rails run **only** on `source_id == "local"` entries. Cloud entries
  never touch `resolve_for_check`, `validate_not_excluded`, or `is_within`
  — the pass-5/pass-6 landmine is closed by construction.
- The `report.roots` array is validated as before. **Cloud sources add no
  new roots** — every cloud member's containment is implicit in "the source
  is in `AccountsRegistry`".
- `is_shared` protection is enforced here too (not only in the scorer) so a
  poisoned report cannot bypass the "shared cloud files informational-only"
  invariant.

### 4.3 New `restore_from_manifest`

Pseudocode changes to `apply/undo.py:188-344`:

```python
def restore_from_manifest(
    manifest_path: Path,
    sources_by_id: dict[str, Source],
    *,
    trash_dir_resolver: TrashResolver | None = None,
    allowed_trash_dirs: list[Path] | None = None,
) -> dict[str, Any]:
    data = json.loads(manifest_path.read_text())
    entries: list[dict] = data.get("entries", [])
    authorized = set(sources_by_id.keys())
    # ... existing roots-array validation unchanged ...
    # ... existing "::" rejection scoped to entries where source_id == 'local' ...

    restored, errors = 0, []
    for entry in entries:
        sid = entry.get("source_id", "local")

        if sid == "local":
            # Existing v0.1.1 flow — F12/H2/H5 rails as today.
            # Delegate the move to sources_by_id["local"].restore_from_trash
            # by constructing a TrashedLocation and calling the source.
            loc = TrashedLocation(
                source_id="local",
                original_path=entry["original_path"],
                local_trashed_at_path=(
                    Path(entry["trashed_at_path"])
                    if entry.get("trashed_at_path") else None
                ),
            )
            try:
                sources_by_id["local"].restore_from_trash(loc)
            except (UndoError, OSError) as e:
                errors.append(str(e))
                continue
            restored += 1
        else:
            # Cloud entry — cloud rails, no local path validation.
            try:
                validate_cloud_entry(entry, authorized_source_ids=authorized)
            except ValueError as e:
                errors.append(f"cloud entry rejected: {e}")
                continue
            src = sources_by_id.get(sid)
            if src is None:
                errors.append(f"no configured source for {sid}")
                continue
            loc = TrashedLocation(
                source_id=sid,
                original_path=entry["original_path"],
                cloud_file_id=entry["cloud_file_id"],
                cloud_trash_id=entry.get("cloud_trash_id"),
            )
            try:
                src.restore_from_trash(loc)
            except SourceNotFoundError:
                errors.append(
                    f"{entry['original_path']}: cloud trash was emptied — "
                    "unable to restore. Check the provider's web UI."
                )
                continue
            except SourceError as e:
                errors.append(f"{entry['original_path']}: {e}")
                continue
            restored += 1

    return {"restored": restored, "errors": errors, "total": len(entries)}
```

Salient details:
- `sources_by_id` is now a **required** parameter. Sub-phase 1 already
  established this pattern for the mover; sub-phase 5 promotes it to undo.
- Local flow still uses `LocalFileSystemSource.restore_from_trash`, which in
  turn calls `local_restore` → `validate_restore_paths`. The H2/F12/H5 rails
  run exactly once per entry via the shared helper. The pass-5 finding
  ("`restore_from_trash` bypasses undo validations") is closed because the
  only entry point into `local_restore` is via `LocalFileSystemSource`, and
  that method now goes through `validate_restore_paths` (already fixed in
  sub-phase 1 update — sub-phase 5 test locks it in).
- Legacy `restore_from_manifest(manifest_path)` calls without `sources_by_id`
  are supported for one release: if the arg is None, construct
  `{"local": LocalFileSystemSource(is_read_only_scan=False, ...)}` and log a
  deprecation warning. Removed in v0.3.

### 5.2 Pre-trash drift check

Every source implements `get_metadata(record) -> SourceMetadata`. For local
records `SourceMetadata` is empty and `_pre_trash_drift_check` falls back to
the existing `_verify_unchanged(path, size, mtime)` from `apply/mover.py:128`.

For cloud records:

```python
def _pre_trash_drift_check(member: ReportMember, src: Source) -> None:
    if member.source_id == "local":
        _verify_unchanged(Path(member.path), member.size, member.mtime)
        return
    # Cloud — re-fetch current etag and abort on mismatch.
    record = _build_file_record(member)
    current = src.get_metadata(record)
    if current.etag != member.etag:
        raise PathChangedError(
            f"cloud etag changed for {member.path}: scan={member.etag!r} "
            f"now={current.etag!r} — rescan and try again."
        )
```

`GoogleDriveSource.get_metadata` currently just replays scan-time fields
(sub-phase 2). Sub-phase 5 upgrades it to optionally re-fetch: add a
`refresh: bool = False` parameter. `_pre_trash_drift_check` calls
`src.get_metadata(record, refresh=True)` so cloud drift is caught against
current state.

### 5.3 Manifest write ordering

Unchanged. `_write_manifest` continues to use tempfile + `fsync` + `os.replace`
+ parent-dir fsync. The new fields are members of `entries[i]` and land in
the same atomic write. Per-file re-flush after every successful move is
unchanged.

### 5.4 Batch failure handling

Contract for partial failures (per AUDIT_LOG invariant "mover MUST NOT abort
the whole apply run on a single entry failure" — but this is scoped to
`OSError` today; sub-phase 5 broadens):

| Failure class                          | Behavior                                                                 |
|----------------------------------------|--------------------------------------------------------------------------|
| `PathChangedError` (local drift)        | Abort mid-apply. Existing v0.1.1 semantics preserved.                    |
| `PathChangedError` (cloud etag drift)   | Abort mid-apply. Same as local. Manifest reflects entries 1..(n-1).      |
| `SourceRateLimitError` (after retries)  | Abort mid-apply. Manifest flushed. User re-runs after cooldown.          |
| `SourceAuthError` (token expired)       | Abort mid-apply. Manifest flushed. User runs `dc auth test` + re-apply. |
| `SourceNotFoundError` (already gone)    | Log per-entry, continue. Count as "already gone". No `trashed_at` written. |
| `SourcePermissionError`                 | Log per-entry, continue.                                                 |
| `OSError` on local `send2trash`         | Log per-entry, continue. Existing v0.1.1 semantics.                      |

The mid-apply abort behavior for auth/rate-limit is intentional: continuing
under a bad token silently produces a manifest with many missed entries.
Aborting on the first auth failure gives the user a clear signal and one
retry to fix. All aborts happen AFTER the manifest is flushed, so entries
1..(n-1) that were trashed successfully are recoverable via `dc undo`.

## 6. Undo integration

### 6.1 Dispatch

Already covered by §4.3 pseudocode: iterate manifest entries; dispatch by
`source_id`. Local flow uses `sources_by_id["local"].restore_from_trash`
(which internally runs `validate_restore_paths` → `local_restore`
→ `shutil.move`). Cloud flow uses `sources_by_id[sid].restore_from_trash`.

### 6.2 Cloud trash was emptied via web UI

`GoogleDriveSource.restore_from_trash` (already implemented, `gdrive.py:353`)
translates HTTP 404 to `SourceNotFoundError` via `_raise_mapped`. The undo
driver catches this per-entry, appends a user-facing error like
`"gdrive:personal://.../foo.pdf: cloud trash was emptied — unable to restore"`,
and continues. The rest of the manifest still restores.

Contract for the user-facing summary at the end:

```
Undo complete: 47 restored, 3 errors
  - /Users/x/foo.pdf: source path already exists, refusing to overwrite
  - gdrive:personal://.../bar.jpg: cloud trash was emptied — check web UI
  - onedrive:personal://.../baz.pdf: rate-limited — retry in 60s
```

### 6.3 Mixed manifest

The dispatch is per-entry, so a manifest with 30 local + 20 cloud + 15
onedrive entries restores each via the correct source. `sources_by_id` is
populated at CLI entry (`cli.undo`) by iterating `AccountsRegistry.list()`
and constructing one source per registered account.

```python
        # +2 for first, +1 for second, 0 for third, etc.  Numbers small
        # relative to under_active_home (+5) so a local always wins.
        w = float(max(0, len(config.retained_cloud_order) - idx - 1))
        m.signals.append((f"retained_cloud_order[{provider}]", w))
        m.score += w
    except ValueError:
        pass
```

### 7.5 Interaction with hardlink / APFS clone

Informational is monotone — see `score_group` today at `rules.py:191-213`.
Adding `is_shared` / `is_singleton_across_sources` extends the same
information-only set. A file that is BOTH a hardlink family member AND a
shared cloud file remains informational; no change to reclaim math (the
member's `size` is not summed into `reclaim_bytes`).

The pre-scoring extraction of `non_info` filters out every informational
member, so the "cloud_when_local_exists" penalty only applies to members
that could otherwise be discard candidates. This avoids the pathological
case where a shared-informational cloud member gets a -3 penalty and then
still counts toward "prefer local" tie-breaks.

## 9. Migration path from v0.1.1 report.json

Old reports have only `path`, `size`, `mtime`, `hash` (plus flags). New
Pydantic model has trailing defaulted fields, so `Report.model_validate(old_data)`
produces a valid `Report` with `source_id="local"` on every member.

The `Report.version` field defaults to `"0.1.1"` today; sub-phase 5 bumps
the default to `"0.2.0"`. The loader treats missing `version` (very old
0.1.0 reports) and `0.1.*` identically — all local.

**Recommendation:** default-to-`local`, preserve full backward compatibility,
NO forced re-scan. Users with a `report.json` from v0.1.1 in a checked-out
runs directory can `dc apply` it under v0.2 without disruption. Explicitly
tested in `tests/apply/test_backward_compat.py`.

Same logic applies to `manifest.json`: missing `manifest_version` → treat
as v0.1.1 → every entry defaults to `source_id="local"` → local rails run.
A v0.1.1 undo continues byte-identical.

## 11. Open questions / decisions the Dev agent must NOT make

Decisions locked in this doc:

1. **Alternative C is chosen.** No `Location` union, no `CloudRef` type.
   `source_id` is the sole dispatch key; the `Path` on cloud FileRecords is
   opaque display data.

2. **Backward compatibility with v0.1.1 reports/manifests is preserved.**
   Missing `version` → v0.1.1 → default `source_id="local"`. No forced
   re-scan.

3. **`_validate_report_paths` DOES NOT resolve cloud paths.** The local
   rails run ONLY on `source_id == "local"` entries. Cloud entries have
   their own `validate_cloud_entry` rails.

4. **`--commit` is global, not per-source.** A single `dc apply --commit`
   flag commits both local and cloud. Rationale: users think in terms of
   "am I confident in this whole run" — a `--commit-local` /
   `--commit-cloud` split doubles the interaction surface for negligible
   safety gain. The pre-trash re-verify (etag + size/mtime) already gates
   each entry individually.

5. **Cross-cloud ordering is folded into the same scoring pass**, not a
   second pass. `retained_cloud_order` is applied inside `_score_one` as
   an additive score contribution. Rationale: keeps the scorer single-pass,
   avoids ordering-dependent bugs. Second-pass reserved for future
   organizer work in v0.3.

6. **Cloud `Path` collision hardening.** The visual `<source_id>://` in
   `FileRecord.path` collapses to `<source_id>:/` on POSIX (see AUDIT_LOG
   sub-phase 2 note). A regression test locks this in (`test_cloud_path_repr`),
   so a future Python change to colon-in-path semantics fails a red test
   before it can silently reactivate the pass-6 landmine.

Decisions deferred to Dev agent:

- **Batching cloud API calls.** GoogleDriveSource does one API call per
  trash / restore. `google-api-python-client` supports batch requests. Dev
  MAY implement batching if a single `dc apply` moves > 100 cloud files
  and the loop is measurably slow. Otherwise the simple per-file call is
  fine.
- **Progress bar rendering.** Sub-phase 5 must not regress the progress
  UI — Dev decides whether to hook `sys/monitor.py` for cloud trash
  progress. Recommended: per-file tick, no bandwidth counter (cloud trash
  is a metadata op, not a byte transfer).
- **Manifest gzip compression.** With mixed manifests carrying etag +
  cloud_file_id strings the manifest grows ~2x. Dev may choose to gzip
  on write if profiling shows a real-world manifest > 5 MB. Not required.

That is the complete v0.2 sub-phase 5 contract.
